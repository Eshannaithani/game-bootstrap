# Mobile Game SOP, condensed by section

Distilled from the owner's Build & Ship Playbook. Section numbers match the full document so the two can be read together. Adopt sections 1, 2, 10, 11 and 13 before writing gameplay code.

The thread through all of it: the expensive bugs were silent. A plausible wrong number, an event that never arrived, a code path that compiled away, a success log for a call that did nothing. Confirm the outcome, not the call.

1. **Author UI in the editor, never at runtime.** Every UI object is a real GameObject in a scene or prefab; code finds and binds, it does not create. Pattern: `EditorBake()` (editor-only, idempotent, from a Tools menu) plus `AcquireOrBuild()` at runtime, and every change must also run on the bind path. Idempotency keys live on the child object, never in a cached field.
2. **One source of truth for every economy number.** No player-visible number is a literal; all copy builds from one constants class. Grep for hardcoded figures before every release. Stacking must be explicit. A store or platform name is compiled per platform and verified in the built assembly. Rewards are a function of production rate, never of balance. Exponential curves compute in double, return long, clamp to a ceiling and floor at a minimum; sweep the whole level range in a test.
3. **Advertised perks are traced to their call sites** before they ship. Widen the code or narrow the copy.
4. **Split ownership from delivery in IAP.** `Owned` persists immediately; `Delivered` only when the goods are durable on disk. Retry wherever delivery becomes possible. Fail toward paying twice, never toward never paying.
5. **Save migrations need a schema stamp**, set in the constructor only, with a one-time fixup on load. Document what a destructive reset preserves, on the reset itself.
6. **Verify by rendering, not by reading.** Two tools early: an edit-mode panel renderer and a play-mode capture harness at device resolution. Only play mode catches runtime-only bugs.
7. **Text, fonts, layering.** Know the font's character set; plain ASCII everywhere. One shared text material. Font asset before material. A written sort-order ladder (HUD 6, popups 20, toast 30) with a coordinator.
8. **Build size: measure first.** Native code, not art, was 54 percent. Stripping and minification break reflection; prove keep-rules held by grepping `usage.txt` and `mapping.txt`, and upload `mapping.txt` to the store.
9. **Store screenshots: script the staging** with a save fixture written through constructors; back the real save up into a subfolder; commit only PNGs.
10. **Analytics: decide the schema first.** One constants file for names, one wrapper per SDK, a written list of every event before any is implemented. Minimum from day one: tutorial start, every step, complete, abandon; level start, complete, fail; purchase with localized price and ISO currency plus a first-purchase event; ad request, fill, impression, completion, click and each failure; every currency source and sink; session length, count and exit point. Nothing collects before consent (ATT on iOS, a CMP on Android and EU). SDK allow-lists must be declared in the settings asset and cross-checked in code. Segment with user properties (notification permission read live, install age from a first-launch stamp outside the save, payer status). Batch choke-point events by reason and flush on a boundary. Re-audit after every SDK bump.
11. **Multi-device UI on day one.** One reference resolution, one CanvasScaler mode enforced everywhere, a SafeArea container under every canvas with all four insets, edge anchoring for anything that must keep clearance, one shared group shift for collisions. Decide orientation lock; test the smallest and largest screens continuously.
12. **Receipt verification: the client is hostile.** Use the validation result, match product ids, store transaction ids and reject replays, key consumable grants to the transaction, persist entitlements, entitlement outranks remote flags, dev overrides inside a development-build define.
13. **Save architecture is decided at project start.** Ask: IAP, long progression, multi-device, competitive, cross-platform, purchasable currency. Options: local file (protects nothing), platform cloud (uninstall and same-account devices), backend account (everything, costs money). Local at minimum: atomic writes, quarantine corrupt saves, a checksum, schema stamps, known serializer failure modes.
14. **Performance patterns.** One pooling API keyed by prefab with a safe fallback and a kill switch. Poll UI at 0.25 to 1 s instead of Update, cancel in OnDisable, retry backoff only on failure, short-TTL caches for scene queries. No LINQ or string concatenation in hot paths, cache Camera.main, hoist WaitForSeconds. Split static from changing UI onto separate canvases. Measure before optimising.
15. **Pre-launch checklist** runs on a device build: money, analytics, consent, saves, devices and layout, performance, content, build. The ship skill carries the full list.
16. **Habits.** Validate a detector before trusting a zero. Measure the thing, not a proxy. A staging tool can contaminate evidence. Confirm a write landed in the file. Prefer structural fixes to balanced pairs. `StopCoroutine(Method())` is a no-op. Ask for a review at a moment of success with persisted gating. Count references before a shared change. Adversarial review before money code. Fail in the safe direction. Write the why in the comment.
